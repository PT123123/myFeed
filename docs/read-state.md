# 已读记录与「只看未读」

2026-09-27。这片落在 1.4.2 / versionCode 9，平板当前装的是 1.4.3 / versionCode 10。

## 要解决的问题

relay 同步进来 21 个源之后，首页一次刷新就是六百多张卡片。这个应用**从来没有记过用户读过什么**：
`grep` 全仓 `已读|unread|isRead` 命中 0 处。症状分两层：

1. 读过的和没读过的长得一模一样。列表按分数排，读完一条回头接着划，下一条往往还是刚看过的那条附近的内容。
2. 下拉刷新之后，同一批条目原样再来一遍。缓存里 `fetchedAt` 是新的，条目却是三天前看过的那六百条。

兴趣流本身没有「读完」的终点（不像 20 条的固定清单），所以没有这份记录的话，用得越久越像在原地打转。

## 决策

**`ReadStateStore`（`data/ReadStateStore.kt`）：一个二进制文件记 `article.id -> 什么时候读的`。**

- 落在 `filesDir/read_state.bin`，不放 `cacheDir`（系统会在存储紧张时静默清空），也不放
  SharedPreferences（每次点开源都要重写整份 XML 偏好文件）。
- 格式和 `FeedCache` 同一套：魔数 `MFRD` + 版本 + 条数 + 每条「长度前缀 UTF-8 字符串 + int64 时间」。
  复用了 `FeedCache.kt` 里的 `writeStr/readStr`（可见性从 `private` 改成 `internal`）。
- 键是 `Article.id`，不是 `link`。理由和抓取端去重一致：同一篇的链接常有带 token 的变体。
  设备实测的 id 长这样：`appinn:https://www.appinn.com/priprinter/`（源 id + 身份链结果）。
- 清理：只留 90 天内、最多 4000 条，读和写两边都过 `prune`。上限不是防「用太久」，是防孤儿键 ——
  源改版换了 guid 之后旧 id 永远匹配不上，不清就只会长。
- 文件判坏（魔数不对、版本不对、条数离谱、半截）就当没读过，并**顺手删掉**。
  已读记录丢了只是回到「全都新鲜」，不值得弹错误态。
- 写盘先 `.tmp` 再原子改名；`write` 加 `@Synchronized`（连点几条会并发写同一个 `.tmp`，
  交错出来的半截文件下次启动直接判损坏，症状是已读记录整体清零）。

**界面做三件事，都不改排序**（`FeedReaderApp.kt`）：

- `openArticle` 里 `viewModel.markRead(article)` —— **点开即已读**，内置浏览器和交给系统浏览器都算。
- 读过的标题从 `onSurface` 压到 `onSurfaceVariant`。不加徽章、不整卡变灰：
  点开即已读会误伤（手滑划到就算读过），压暗是提示，整卡变灰容易让人以为内容被删了。
- 分类 chips 行末尾多一个「只看未读」，带当前分类下的未读条数；筛空时空态文案会说明是被筛掉的、怎么退回去。

## 已知取舍

- **不做「读完」判定。** 停留时长和滚动位置要为每篇存状态，代价太大；现在这一份只回答「点开过没有」。
- **不用已读去扣分。** `Ranker` 的分数是「为什么推这条」的唯一依据，把可见性塞进排序里，
  以后查「这条为什么排前面」就说不清了。所以已读只做压暗 + 隐藏，一分不改。
- **本轮会话刚读的条目，即使开着「只看未读」也留在屏幕上**（`readBeforeSession`）。
  不这么做的话：点开一条 → 标记已读 → 从阅读页返回 → 那条瞬间被筛掉、列表往上跳一格，
  症状像「我点开的内容凭空消失了」。下次冷启动没有这条豁免。
- **没有「标记未读」的单条反悔入口**，只有设置页「缓存」一节里的整份「清空已读记录」（副标题带条数）。
  误点一条要恢复只能整体清空 —— 单条反悔得在列表上长按，那是另一个交互设计，没做。
- 已读记录跟着 `Article.id` 走，所以**换设备/清数据即归零**，不在 OPML、不在 relay 同步范围内。
- 深链、扫一扫带进来的伪条目（网页搜索那条 `searchArticle`）也会记已读。它的 id 是稳定的
  （引擎 + 关键词），会跟着 90 天过期，不会长驻。

- **没人眼看过的是**：压暗后的标题、分类行末尾那颗「只看未读」chip、以及筛空时的新空态文案。

## 要你动手的两件事

1. 首页划到分类 chips 那一行，看末尾有没有「只看未读」，点亮再点掉，列表该整屏换一批；
2. 随便点开两条，返回后标题该变淡；关掉再开应用，那两条该还是淡的（这才说明落盘成功了）。

**第 2 件事现在不用动手也能看**：平板上我**故意留着**探针造的那份 `read_state.bin`（181 字节，
1.4.3 冷启动 `logcat` 报 `已读记录 3 条`），里面是「小众软件」这三条的真实 id ——
首页划到这三条该是淡的，「只看未读」一点它们就该消失：

- `appinn:https://www.appinn.com/priprinter/`
- `appinn:https://www.appinn.com/aria2-next/`
- `appinn:https://www.appinn.com/hermes-7-free-models/`

看完想复原：设置页 →「缓存」→「清空已读记录」（或 `adb -s <序列号> shell run-as com.example.feedreader rm files/read_state.bin`）。
重跑探针：`python tools/read_state_probe.py`（推送那步走 `echo <b64> | base64 -d` ——
`adb exec-out` 不转发 stdin，直接喂管道会得到 0 字节文件，症状看着像解析坏了）。

设置页 →「缓存」→ 最后一行「清空已读记录」，副标题会报条数，点它能全部回到未读。
